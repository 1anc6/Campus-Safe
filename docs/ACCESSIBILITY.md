# CampusSafe accessibility check (WCAG 2.2 AA)

Checked on 7 November 2026, against `main` with real-time updates (04beb73) merged in.
Target: WCAG 2.2 level AA, as set in `PRODUCT.md`. The app is used under stress on phones, so this
check put weight on large targets, contrast in both themes, reduced motion, never using colour
alone, and an SOS button that works for everyone.

**Result:** the automated check finds no serious or critical violations, apart from one documented
and accepted exception (overlapping map pins, see below). All manual checks pass. What is left is
listed under [Not fixed](#not-fixed).

## Method

### Automated: `npm run a11y`

`scripts/a11y-audit.mjs` runs [axe-core](https://github.com/dequelabs/axe-core) 4.x through
Playwright. It uses the rule tags `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, `wcag22aa` and
`best-practice`.

- **Every page, for every role.**
  - Public: login, signup, the anonymous report (steps 1 and 2), track, forbidden.
  - Student: onboarding, home, SOS countdown, profile panel, bell, report form (empty and with
    errors), my reports, report detail, live SOS.
  - Responder: assigned alerts, alert detail, incident detail.
  - Admin: dashboard, command palette, SOS map, SOS case, incidents, incident case, anonymous,
    users, responders, analytics, alerts.
- **Each page in light and dark themes, at 360px (phone, touch emulation) and 1280px (desktop),**
  with `prefers-reduced-motion: reduce` so nothing is checked mid-animation.
- **Real data behind every detail page.** Before checking, the script signs in as the test
  student and sends an SOS using the keyboard double press (which also tests that path). It files
  one report, then signs in as admin and assigns the SOS to the test responder's unit.
- **How to run it:** start `npm run dev:local`, then run `npm run a11y`. Set `A11Y_BASE_URL` if
  the app is not on port 8080. `A11Y_ONLY`, `A11Y_THEMES` and `A11Y_WIDTHS` narrow the run, and
  `A11Y_JSON=<file>` saves the full results. The script exits with status 1 if any serious or
  critical violation is found that is not in its documented `EXCEPTIONS` list, or if a page could
  not be checked.
- **Browser:** it uses Playwright's Chromium when installed, otherwise the system Chrome or Edge.

### Manual

All manual checks were run with scripted Playwright in Chrome, light and dark, at 360px and
1280px.

- **Keyboard only:** Tab through all 19 pages for every role, in both themes and at both widths
  (76 walks). Each Tab stop was checked for a visible focus indicator, for focus landing on a
  hidden element, and for keyboard traps.
- **SOS button:** keyboard hold, keyboard double press, touch tap and double tap, mouse hold and
  short hold. Also an assistive-technology click: a `click()` with no pointer or key events, which
  is what a screen reader's double-tap or switch access sends. Checked what is announced, plus the
  countdown dialog's focus, Tab, Escape and focus return.
- **Live updates (new since 04beb73):**
  - Admin is typing a reply and has focus on a dashboard queue link.
  - The responder has focus on a quick-reply button.
  - The student sends a chat message, then the responder marks "I've arrived".
  - Checked that focus and typed text stay put, that the new message lands in a polite live
    region, and that the student hears the new status.
- **Reduced motion:** `document.getAnimations()` on the student, admin and responder screens with
  reduce turned on.
- **Screen-reader names and roles:** checked by reading the accessibility tree and markup.
  Examples: the SOS button, NeuSelect triggers, map markers, chart alternatives, the counter pills
  and the status stepper.
- **Not covered:** no test with a real screen reader (NVDA, VoiceOver or TalkBack) or on a real
  phone. That is the most useful next check.

## Notes for other work

- **Changed visible text:** only the SOS hint toast in `src/components/student/sos-flow.tsx`.
  Everything else added is screen-reader-only text: the SOS live region and hint, the stepper
  state words, the chart tables and the wordmark's "home". These strings still need translation
  in the multi-language work.
- **Colour tokens:** `src/styles.css` holds the new values, and `DESIGN.md` is updated to match.
  If a token changes, re-run `npm run a11y`. The tinted-chip contrast is the easiest thing to
  break.
